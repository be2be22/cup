# پنل سبک مدیریت کانفیگ WS (Xray + Nginx + Docker)

پنل مینیمال برای ساخت/حذف/فعال-غیرفعال کردن کاربران VLESS+WebSocket، بدون
وابستگی به پنل‌های سنگین مثل Marzban یا X-UI.

## معماری

```
اینترنت
   │
   ▼
 Nginx (پورت 80، تنها پورت expose‌شده)
   ├── مسیر ${WS_PATH}  -->  Xray (vless+ws، پورت داخلی 10000)
   └── بقیه مسیرها      -->  Panel (Flask، پورت داخلی 5000)
```

- **چرا فقط پورت 80؟** چون بسترهایی مثل Bunnyshell معمولاً خودشان روی دامنه‌ای
  که به‌صورت خودکار می‌دهند TLS/HTTPS را در لایه‌ی edge مدیریت می‌کنند و به
  اپلیکیشن شما با HTTP ساده روی یک پورت وصل می‌شوند. اگر روی سرور خودتان
  (VPS خام، بدون edge TLS) دیپلوی می‌کنید، باید یک بلاک SSL (مثلاً با
  Let's Encrypt/certbot) به `nginx/default.conf.template` اضافه کنید تا پورت
  443 مستقیماً TLS بدهد.

## اجزا

- **xray** – کانتینر رسمی `teddysun/xray`, کانفیگش توسط پنل نوشته می‌شود.
- **panel** – یک اپ Flask سبک با SQLite، مدیریت کاربران و ساخت لینک اشتراک.
- **nginx** – مسیر `WS_PATH` را به Xray و بقیه را به پنل هدایت می‌کند.

پنل هر بار که کاربری اضافه/حذف/فعال/غیرفعال می‌شود:
1. فایل `config.json` مربوط به Xray را دوباره می‌سازد (روی volume مشترک).
2. با استفاده از `docker.sock` کانتینر `xray` را ری‌استارت می‌کند تا کانفیگ
   جدید لود شود (چند صدم ثانیه قطعی کوتاه، اتصالات فعال جدید بی‌درنگ وصل می‌شوند).

## اجرا (لوکال یا هر VPS داکردار)

```bash
cp .env.example .env
# مقادیر ADMIN_USER / ADMIN_PASS / SECRET_KEY / WS_PATH را عوض کن
docker compose up -d --build
```

سپس روی `http://<IP-یا-دامنه>/` وارد پنل شو.

## دیپلوی روی Bunnyshell

Bunnyshell یک محیط بر پایه‌ی Docker/Kubernetes است که برای هر دیپلوی یک
دامنه‌ی اختصاصی با HTTPS می‌دهد. مراحل کلی:

1. این پوشه (شامل `docker-compose.yml`) را داخل یک ریپازیتوری گیت (GitHub/GitLab)
   قرار بده — Bunnyshell معمولاً از روی ریپو دیپلوی می‌کند.
2. در پنل Bunnyshell یک Environment جدید بساز و ریپو را وصل کن؛ Bunnyshell
   `docker-compose.yml` را می‌خواند و سه سرویس (nginx, xray, panel) را بالا می‌آورد.
3. متغیرهای محیطی (`ADMIN_USER`, `ADMIN_PASS`, `SECRET_KEY`, `WS_PATH`, ...) را
   از بخش Environment Variables خود Bunnyshell ست کن (به‌جای فایل `.env`).
4. فقط سرویس **nginx** باید به بیرون expose شود (پورت 80) — Bunnyshell دامنه و
   گواهی SSL را خودش روی همین پورت سوار می‌کند.
5. بعد از دیپلوی، دامنه‌ای که Bunnyshell به تو می‌دهد (مثلاً
   `xxxx.bunnyshell.app`) هم آدرس پنل توست و هم هاست کانفیگ VLESS.

> نکته: چون هر دیپلوی روی Bunnyshell دامنه‌ی متفاوتی می‌گیرد، پنل به‌طور خودکار
> از هدر `Host` درخواست برای ساخت لینک اشتراک‌گذاری استفاده می‌کند — نیازی به
> ست‌کردن دستی دامنه نیست.

## نکات امنیتی مهم

- حتماً `ADMIN_PASS` و `SECRET_KEY` پیش‌فرض را عوض کن.
- در صورت امکان روی Bunnyshell دسترسی به پنل را با IP allow-list یا لایه‌ی
  احراز هویت اضافه‌ی خودِ پلتفرم محدود کن.
- کانتینر پنل به `docker.sock` دسترسی دارد (برای ری‌استارت Xray). این یعنی
  پنل عملاً به داکر هاست دسترسی مدیریتی دارد؛ فقط روی محیط‌های قابل‌اعتماد
  اجرا کن و پسورد پنل را قوی نگه دار.
- این استک صرفاً زیرساخت پروکسی/تانل می‌سازد؛ مسئولیت رعایت قوانین محلی و
  شرایط استفاده‌ی Bunnyshell و ارائه‌دهنده‌ی سرور بر عهده‌ی خودت است.

## تغییر پروتکل

اگر بعداً خواستی VMess یا Trojan اضافه کنی، کافی‌ست:
1. یک inbound جدید در `rebuild_xray_config()` (در `panel/app.py`) اضافه کنی.
2. یک location جدید متناظر در `nginx/default.conf.template` بسازی.
