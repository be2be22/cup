# ربات جام جهانی ۲۰۲۶ - نسخه alwaysdata

سیستمی که وضعیت بازی‌های جام جهانی رو از **ESPN** (رایگان، بدون نیاز به کلید API)
می‌خونه و به‌صورت خودکار به یه کانال تلگرام گزارش می‌ده: پیش‌بازی، آپدیت زنده،
گل/کارت، پنالتی، توقف بازی و گزارش پایانی.

علاوه بر پست‌های خودکار کانال، یه **منوی دکمه‌دار تعاملی** هم داره که هرکسی
می‌تونه توی چت خصوصی با ربات باز کنه و بپرسه: بازی قبل چی شد، الان چه بازی‌ای
زنده‌ست، بازی بعدی کِی هست + یه تحلیل کوتاه، و برنامه‌ی امروز.

هیچ کتابخونه‌ی خارجی نیاز نداره (فقط کتابخونه‌های استاندارد پایتون)، پس نیازی
به `pip install` نیست.

## ساختار پروژه

```
worldcup/
├── config.json            تنظیمات (چنل تلگرام، لیگ ESPN)
├── state.json              حافظه‌ی وضعیت (خودکار آپدیت می‌شه، دست نزنید)
├── webhook.py               ← نقطه‌ی ورود سایت دوم (وبهوک منوی تعاملی)
├── lib/
│   ├── api_client.py        کلاینت ESPN
│   ├── formatter.py         قالب‌بندی پیام‌های فارسی
│   ├── state_manager.py     ذخیره‌سازی وضعیت روی فایل
│   ├── telegram_sender.py   ارسال پیام، کیبورد اینلاین، ادیت پیام، webhook API
│   ├── ai_analysis.py       تحلیل پیش‌بازی با هوش مصنوعی (اختیاری)
│   ├── analysis_data.py     تحلیل استاتیک، فقط fallback وقتی AI تنظیم نشده
│   ├── analysis_builder.py  ترکیب AI + fallback (مشترک بین کران و منو)
│   ├── bot_menu.py          چیدمان دکمه‌های اینلاین منو
│   └── bot_logic.py         متن پاسخ هر دکمه (زنده/قبلی/بعدی/امروز/راهنما)
└── scripts/
    ├── main_monitor.py      ← این تنها اسکریپتیه که باید cron کنید
    ├── set_webhook.py       یه‌بار از طریق SSH اجرا می‌شه (ثبت آدرس وبهوک)
    ├── check_setup.py       برای تست دستی بعد از دیپلوی
    └── scheduler.py, prematch.py, live_update.py, event_monitor.py,
        penalty_monitor.py, delay_alert.py, postmatch.py  (توسط main_monitor صدا زده می‌شن)
```

## قابلیت‌های منوی تعاملی ربات

وقتی کسی به ربات (نه کانال) پیام `/start` بده، این دکمه‌ها رو می‌بینه:

| دکمه | کاری که می‌کنه |
|---|---|
| 🔴 وضعیت بازی زنده | نتیجه و آخرین اتفاقات بازی‌ای که الان در جریانه |
| 📋 نتیجه بازی قبلی | نتیجه‌ی آخرین بازی‌ای که تموم شده |
| ⏭ بازی بعدی + تحلیل | تاریخ/ساعت (شمسی) و یه تحلیل کوتاه پیش از بازی بعدی |
| 📅 برنامه امروز | همه‌ی بازی‌های امروز با وضعیت هرکدوم (ایده‌ی اضافه) |
| ℹ️ راهنما | توضیح کوتاه هر دکمه |

این منو کاملاً جدا از cron کار می‌کنه: یه **وبهوک** (webhook.py) هر بار که کسی
دکمه‌ای می‌زنه، لحظه‌ای صدا زده می‌شه و جواب رو ادیت می‌کنه - نیازی به یه
پروسه‌ی همیشه‌روشن نیست، پس با پلن رایگان alwaysdata هم سازگاره.

## مراحل نصب روی alwaysdata

### ۱. آپلود فایل‌ها
پوشه‌ی `worldcup/` رو با SFTP/FTP، از پنل alwaysdata (File Manager) یا با
`git clone` از طریق SSH (پایین‌تر توضیح داده شده) آپلود کنید، مثلاً به مسیر
`~/worldcup/`.

### ۲. متغیرهای محیطی
پنل alwaysdata → **Sites** → سایت خودتون → **Environment** و این‌ها رو اضافه کنید:

| نام | مقدار |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن ربات تلگرامتون (از BotFather) |
| `TELEGRAM_WEBHOOK_SECRET` | یه رشته‌ی تصادفی دلخواه (برای امنیت وبهوک - پیشنهادی) |
| `AI_API_BASE_URL` | اختیاری - مثلاً `https://9router-production-2f7f.up.railway.app/v1` |
| `AI_API_KEY` | اختیاری - کلید API همون سرویس |
| `AI_MODEL` | اختیاری - پیش‌فرض `oc/mimo-v2.5-free` |

این متغیرها باید هم روی سایتِ cron و هم روی سایتِ وبهوک (مرحله‌ی ۵) تنظیم بشن.

**هیچ‌وقت این مقادیر رو مستقیم توی فایل‌های کد ننویسید** - همیشه از همین بخش
Environment پنل استفاده کنید.

⚠️ اگه توکن ربات یا کلید AI رو قبلاً جایی (مثل یه چت یا لینک گیت‌هاب عمومی)
به‌صورت متن ساده فرستادید، بعد از تنظیم اینجا، از پنل همون سرویس یه مقدار
جدید بسازید و قبلی رو باطل کنید.

### ۳. ربات رو ادمین کانال کنید
ربات تلگرامتون باید عضو و **ادمین** کانالی باشه که `channel_id` توی
`worldcup/config.json` بهش اشاره می‌کنه (فعلاً `-1004412008547`).

### ۴. تست دستی گزارش‌های کانال
از طریق SSH:
```bash
cd ~/worldcup
python3 scripts/check_setup.py
```
این اسکریپت تنظیمات محیطی، اتصال به ESPN، و ارسال پیام تست به تلگرام رو چک می‌کنه.

### ۵. تنظیم Scheduled Task (کران)
پنل alwaysdata → **Advanced** → **Scheduled tasks (Cron)** → یه تسک جدید:

- **Command:** `python3 /home/YOUR_USERNAME/worldcup/scripts/main_monitor.py`
- **Frequency:** هر ۱ تا ۲ دقیقه

همین یک تسک کافیه - `main_monitor.py` خودش پیش‌بازی، آپدیت زنده، گل/کارت،
پنالتی، توقف و گزارش پایانی رو مدیریت می‌کنه؛ نیازی به چند تسک جدا نیست.

### ۶. راه‌اندازی منوی تعاملی (وبهوک)
این بخش با کران فرق داره چون باید همیشه روی یه آدرس HTTPS در دسترس باشه، پس
یه **سایت پایتون (WSGI) جدا** لازم داره:

1. پنل alwaysdata → **Web** → **Sites** → **Add a site** → یه ساب‌دامین یا
   مسیر جدید بسازید (مثلاً `bot.yourdomain.alwaysdata.net`)، نوعش رو
   **Python (WSGI)** بذارید.
2. مسیر برنامه (working directory) رو به همون `~/worldcup` بدید و entry
   point/WSGI callable رو به `webhook:application` تنظیم کنید (یعنی فایل
   `webhook.py`، تابع `application`). جزئیات دقیق فیلد entry point بسته به
   نسخه‌ی پنل ممکنه کمی فرق کنه؛ در مستندات alwaysdata با عنوان
   "Python site" / "WSGI" قابل جستجوئه.
3. همون متغیرهای محیطی مرحله‌ی ۲ (به‌خصوص `TELEGRAM_BOT_TOKEN` و
   `TELEGRAM_WEBHOOK_SECRET`) رو روی این سایت جدید هم تنظیم کنید.
4. از طریق SSH، آدرس عمومی همین سایت رو به تلگرام معرفی کنید:
   ```bash
   cd ~/worldcup
   export TELEGRAM_BOT_TOKEN=...      # همون مقداری که تو پنل گذاشتید
   export TELEGRAM_WEBHOOK_SECRET=... # اگه تنظیم کردید
   python3 scripts/set_webhook.py https://bot.yourdomain.alwaysdata.net/
   ```
   خروجی باید `"ok": true` بده. برای چک کردن وضعیت وبهوک: `python3 scripts/set_webhook.py --info`
5. توی تلگرام به ربات پیام `/start` بدید - باید فوراً منو با دکمه‌ها ظاهر بشه.

⚠️ نکته: اکشن «⏭ بازی بعدی + تحلیل» ممکنه اگه `AI_API_BASE_URL` تنظیم شده
باشه چند ثانیه طول بکشه (چون یه درخواست به سرویس AI می‌زنه). این طبیعیه؛
اگه سرویس AI جواب نده، خودکار به تحلیل استاتیک برمی‌گرده.

## نکات مهم

- مصرف منابع سمت کران خیلی سبکه (هر اجرا چند ثانیه، بدون پروسه‌ی دائمی) و با
  پلن رایگان (۰.۲۵ CPU / ۲۵۶MB) سازگاره. سایت وبهوک هم فقط وقتی کسی دکمه‌ای
  می‌زنه بیدار می‌شه، نه یه سرویس همیشه در حال اجرا.
- تحلیل پیش‌بازی (چه توی کانال، چه توی منوی ربات) اول سراغ AI می‌ره؛ اگه
  `AI_API_BASE_URL`/`AI_API_KEY` تنظیم نشده باشه یا درخواست fail بشه، به دیتای
  استاتیک توی `analysis_data.py` برمی‌گرده (اگه تیم‌ها اونجا موجود باشن)، وگرنه
  بدون بخش تحلیل پیام می‌فرسته - یعنی هیچ‌وقت کل پیام به‌خاطر مشکل AI از دست
  نمی‌ره.
- `state.json` حافظه‌ی این‌که چه پیامی قبلاً فرستاده شده رو نگه می‌داره تا پیام
  تکراری نره؛ اگه می‌خواید از صفر شروع کنید، محتواش رو به
  `{"active_matches": [], "match_states": {}, "last_scheduler_run": null}`
  ریست کنید.
- `TELEGRAM_WEBHOOK_SECRET` اختیاریه ولی توصیه می‌شه؛ بدونش هرکسی که آدرس
  سایت وبهوک رو حدس بزنه می‌تونه براش درخواست جعلی بفرسته.

## دیپلوی از طریق GitHub + SSH (به‌روز کردن کد روی سرور)

پایین‌تر (بخش «راهنمای دیپلوی») روش کامل رو دارید: چطور از طریق SSH به سرور
alwaysdata وصل بشید و کد رو مستقیم از این ریپازیتوری بگیرید یا آپدیت کنید.
